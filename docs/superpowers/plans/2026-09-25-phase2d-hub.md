# Phase 2d · Hub page onto the family design: implementation plan

> **For agentic workers:** follow superpowers:executing-plans, test first.
> **Design:** run `/impeccable` typeset, clarify and adapt on `index.html`. Finish with `impeccable detect` and a desktop and 390 px screenshot pass.

**Goal:** the Hub (`index.html`, static, with no build step) reads as the front door of the same product as the four sites. It takes:
- the family frame (PREDICTOR wordmark and the sport switcher);
- the stage;
- Barlow type;
- one notched card per sport, in that sport's accent;
- the honesty rule stated once, plainly.

**Out of scope:** the live "this weekend" ticker of each sport's next pick and season record. That is roadmap Phase 4, step 13. It needs each API reachable from the Hub (CORS or a same-origin proxy on the VPS), so it is a deployment decision, not a restyle.

## Constraints

- **No build step.** The tokens are inlined as plain CSS custom properties. A test parses `packages/predictor-ui/src/tokens.css` and fails if any inlined value drifts from it.
- **Links** go to the VPS subdomains. NFL and CFB get their own cards, pointing at `sports…/?sport=nfl` and `?sport=cfb`.
- **Status is honest words, 12 px or larger:** "In season" or "Preseason". There are no invented dates.
- **Removed:** the emoji icons, Inter, radial gradients, and hover lift (motion that carries no meaning).

## Tasks

1. **Tests** (`tests/hub.test.mjs`):
   - the frame and switcher;
   - five sport cards, each with `data-sport` and a correct link;
   - the token values match `tokens.css`;
   - no Inter, no radial-gradient, no emoji;
   - the status words, with badges of 12 px or larger;
   - the honesty line.
2. **Rewrite `index.html`** against those tests.
3. **Verify:** run the detector, capture screenshots, commit and push.
